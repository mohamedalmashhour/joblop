# Resident Job Platform Core 1.0 Baseline

Status: APPROVED FOUNDATION BASELINE

This document freezes the accepted Platform Core 1.0 foundations for Resident Workforce OS. Ordinary feature work must build on this frozen core rather than bypass it. Completed Platform Core entities may not be renamed, redesigned, or materially changed without an approved Architecture Change Request.

## Core Boundary Statements

- Job Request is the commercial and operational source of truth for staffing demand.
- RoleDefinition remains an operational role under WorkGroup for Phase 01.
- GlobalOccupation is deferred to a future Architecture Change Request.
- All downstream operational records must reference the originating Job Request.
- Platform Core 1.0 is not dispatch, worker offer, assignment, attendance, timesheet, invoice, payment, notification, AI, reporting, or payroll implementation.

## Downstream Build Rule

Every future operational phase must reference the Platform Core 1.0 baseline before implementation. If a future phase needs to change any accepted entity, lifecycle, permission, ownership rule, or source-of-truth boundary listed here, work must stop for owner review and the appropriate Architecture Change Request.

## Validation Rule

Each future implementation phase must validate:

- no bypass of Platform Core ownership
- no unauthorized schema or permission expansion
- no cross-tenant leakage
- safe authorization errors
- immutable audit where required
- compatibility with Job Request as the originating source record

## Final Baseline Statement

Platform Core 1.0 is frozen as the accepted foundation for Resident Job Phase 01. Future implementation may extend the platform only through approved downstream boundaries.
